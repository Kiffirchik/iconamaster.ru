# Настройка Iconamaster в Windows

Руководство описывает фактическое поведение `setup.ps1` в Windows 10/11. Скрипт привязывает все пути к своему расположению, поэтому репозиторий и родительские каталоги могут содержать пробелы.

## Поддерживаемые оболочки и инструменты

Скрипт работает в обеих поддерживаемых оболочках:

- Windows PowerShell 5.1, входящий в Windows;
- PowerShell 7+ (`pwsh`).

Основной набор инструментов:

| Инструмент | Требование |
| --- | --- |
| Git | установлен и доступен через `PATH` |
| Node.js | `^20.19.0` или `>=22.12.0`; Node.js 21 не поддерживается |
| npm | 10+; проект закрепляет npm 10.8.2 |
| winget | нужен только для `-InstallPrerequisites` |

Проверить среду без изменений можно из корня репозитория:

```powershell
.\setup.ps1 -CheckOnly
```

В PowerShell 7 та же проверка может быть запущена явно:

```powershell
pwsh.exe -NoProfile -File .\setup.ps1 -CheckOnly
```

## Режимы setup.ps1

### Обычная настройка

```powershell
.\setup.ps1
```

Скрипт проверяет Git, Node.js и npm, сверяет `package.json` и `package-lock.json`, затем последовательно выполняет `npm ci`, `npm run check:portability` и `npm run verify`. Если основной инструмент отсутствует или имеет неподдерживаемую версию, запуск завершается до `npm ci` и ничего не устанавливает.

`npm ci` создаёт обычный локальный каталог `node_modules`. Он исключён из Git и не должен копироваться между машинами. На чистой копии `-CheckOnly` не создаёт `node_modules`; если каталог уже существует, режим дополнительно выполняет `npm ls --depth=0`.

### Только проверка

```powershell
.\setup.ps1 -CheckOnly
```

Режим проверяет основной набор, метаданные проекта и переносимость Git-файлов. Он не запускает `npm ci`, не устанавливает программы и сохраняет ненулевой код завершения проверки переносимости.

### Явная установка prerequisites

```powershell
.\setup.ps1 -InstallPrerequisites
```

Только этот флаг разрешает установку недостающих основных инструментов. Скрипт вызывает `winget` с точными идентификаторами и без интерактивного выбора пакета:

- Git: `Git.Git`;
- Node.js LTS и входящий в него npm: `OpenJS.NodeJS.LTS`.

Один и тот же пакет Node.js не устанавливается повторно, если одновременно отсутствуют Node.js и npm. После `winget` скрипт обновляет `PATH` текущего процесса и повторно проверяет версии, а затем выполняет обычную настройку.

`-CheckOnly` и `-InstallPrerequisites` взаимоисключающие: совместный запуск завершается ошибкой до выполнения работы.

### Дополнительная проверка публикации

```powershell
.\setup.ps1 -CheckOnly -ForDeployment
```

`-ForDeployment` добавляет отдельную проверку наличия `ssh`, `scp` и `tar`. Она не запускает эти команды, не проверяет доступ к серверу и не публикует сайт. Без `-ForDeployment` отсутствие этих инструментов не мешает локальной разработке.

### Дополнительная проверка миграции

```powershell
.\setup.ps1 -CheckOnly -ForMigration
```

`-ForMigration` требует локальный `ffmpeg`, но не устанавливает его и не запускает миграцию. Допустим только закреплённый бинарный файл из `tests/fixtures/migration/editorial-cover-assets.json`: скрипт сравнивает SHA-256 исполняемого файла и точную первую строку `ffmpeg -version` с полями `encoder.binarySha256` и `encoder.versionLine` fixture. Любое расхождение завершает проверку контролируемой ошибкой.

Диагностика ошибки миграции сообщает только этот путь относительно репозитория, безопасную категорию отказа и действие `.\setup.ps1 -CheckOnly -ForMigration`, а также ссылается на данное руководство. Она не выводит путь checkout, профиль пользователя или путь к исполняемому файлу.

Оба дополнительных флага можно сочетать друг с другом. Без `-CheckOnly` они выполняются перед обычным `npm ci`; их назначение всё равно ограничено локальной диагностикой.

## winget и Microsoft App Installer

Проверьте доступность менеджера пакетов:

```powershell
winget --version
```

`winget` поставляется компонентом Microsoft **App Installer**. Если команда отсутствует, установите или обновите App Installer от Microsoft через Microsoft Store, затем закройте и заново откройте PowerShell. После установки Git или Node.js также откройте новую оболочку, если новая команда не появилась в `PATH`. Сам `setup.ps1 -InstallPrerequisites` обновляет `PATH` только для своего текущего процесса.

Если основной Git или Node.js не готов, а `winget` доступен, диагностика показывает точную следующую команду `.\setup.ps1 -InstallPrerequisites`. Если `winget` отсутствует, сначала установите или обновите Microsoft App Installer, заново откройте оболочку и выполните `.\setup.ps1 -CheckOnly`. Если повторная проверка сразу после установки всё ещё не видит инструмент, откройте новую оболочку и снова выполните `.\setup.ps1 -CheckOnly`.

Скрипт не устанавливает автоматически PowerShell 7, OpenSSH Client, `tar` или FFmpeg.

## Диагностика

### Политика выполнения PowerShell

Если локальная политика блокирует запуск `.ps1`, используйте обход только для одного процесса Windows PowerShell, не меняя политику системы:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -CheckOnly
```

После успешной диагностики подставьте вместо `-CheckOnly` нужные разрешённые флаги.

### Не найдены ssh или scp

Установите штатный компонент Windows по пути:

**Settings > System > Optional features > Add an optional feature > OpenSSH Client**

После установки заново откройте PowerShell и повторите `-CheckOnly -ForDeployment`. Скрипт не вызывает `Add-WindowsCapability`, не запрашивает административные права и не устанавливает OpenSSH сам.

### Не найден tar

Проверьте команду:

```powershell
Get-Command tar
```

Если она отсутствует, установите или восстановите штатный Windows BSD tar, заново откройте PowerShell и повторите deployment-проверку. Скрипт не скачивает заменяющий бинарный файл.

### Не подходит версия Node.js или npm

```powershell
node --version
npm --version
```

Нужны Node.js `^20.19.0 || >=22.12.0` и npm 10+. В частности, Node.js 20.18.x, 21.x и 22.11.x не проходят проверку. Для явной установки поддерживаемой LTS-версии используйте `-InstallPrerequisites`.

### Ошибка метаданных проекта

`package.json` и `package-lock.json` должны находиться рядом с `setup.ps1`, иметь одинаковое корневое имя пакета, а lockfile должен использовать формат 3. Запускайте Git-копию целиком, не переносите один `setup.ps1` без package-файлов и portability-скриптов.

## Разработка, проверка и публикация

```powershell
npm run dev
npm run check:portability
npm run verify
npm run build:mtw
```

`npm run check:portability` анализирует отслеживаемые Git текстовые файлы и отклоняет локальные Windows-пути, привязанные к профилю конкретного пользователя. Документация, конфигурация и скрипты должны использовать относительные пути, URL или значения времени выполнения.

`npm run build:mtw` только готовит пакет. Ни одна комбинация флагов `setup.ps1` не выполняет deployment, не подключается к MTW и не отправляет изменения в GitHub. Сначала выполните проверки, зафиксируйте изменения и отправьте commit в GitHub; отдельную публикацию на MTW начинайте только после этого и по соответствующей процедуре релиза.

## Секреты

Пароли, токены, SSH-ключи и иные секреты храните вне Git и вне файлов проекта — например, в системном хранилище учётных данных, SSH-агенте или пользовательском каталоге за пределами репозитория. Не добавляйте их в README, npm-конфигурацию, fixture-файлы, команды commit или отчёты. `setup.ps1` не запрашивает, не читает и не выводит секреты.
